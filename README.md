## What is GHOSTRECON?

GHOSTRECON is a fast, accurate web security scanner built for penetration testers and security researchers. It goes beyond simple technology fingerprinting — it actively analyzes security posture, detects vulnerabilities, correlates CVEs, and generates professional HTML reports, all from a single command.

Think of it as **WhatWeb + Nikto + a security header analyzer**, combined into one tool with a clean output and zero noise.

```bash
ghostrecon target.com
ghostrecon target.com --mode redteam
ghostrecon target.com --ai --api-key sk-ant-...
```

## Features

### 🔍 Technology Fingerprinting (50+ detections)
Detects servers, CMS platforms, frameworks, frontend libraries, analytics, CDNs, and security tools — with version numbers where available.

| Category | Examples |
|---|---|
| Servers | Nginx, Apache, IIS, LiteSpeed |
| CMS | WordPress, Drupal, Joomla, Bitrix, Magento |
| Frameworks | Laravel, Django, Flask, Rails, Next.js, Express |
| Frontend | React, Vue, Angular, jQuery (with version), Bootstrap |
| Analytics | Google Analytics, GTM, Hotjar, Facebook Pixel |
| CDN/Hosting | Cloudflare, Vercel, Netlify, AWS CloudFront, Akamai |
| Security | reCAPTCHA, hCaptcha, Cloudflare Turnstile |

### 🛡️ Security Analysis
- **Missing security headers** — CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy
- **Clickjacking detection** — flags when both X-Frame-Options and CSP frame-ancestors are absent
- **Outdated library detection** — compares detected versions against known CVEs (e.g. jQuery 2.x → CVE-2020-11022)
- **Cookie security** — checks HttpOnly, Secure, SameSite flags on session cookies
- **SSL/TLS analysis** — detects certificates expiring within 30 days

### 🔎 Endpoint & Subdomain Discovery
Checks a curated set of ~300 high-value paths and ~600 subdomain labels concurrently with
body verification to eliminate false positives: `/.env`, `/.git/HEAD`, `/phpinfo.php`,
`/adminer.php`, `/graphql`, `/swagger.json`, `/api/`, `/debug`, `/console`, and more.

Pass `--deep` (alongside `--dirbrute` and/or `--subdomains`) to switch to the large
permutation wordlists in `config/wordlists/endpoints_large.txt` (250,000+ candidate paths)
and `config/wordlists/subdomains_large.txt` (150,000+ candidate labels), generated by
combining the curated seed list with an English dictionary across common prefixes,
suffixes and file extensions. Deep mode automatically raises concurrency (200 for
dirbrute, 300 for DNS) and streams results in chunks so scanning hundreds of thousands
of candidates stays practical. Regenerate or resize the large wordlists with
`python3 scripts/generate_wordlists.py` (edit `TARGET_ENDPOINTS` / `TARGET_SUBDOMAINS`
at the top of that script to change the target count).

### 📧 Email Harvesting
Extracts valid email addresses from page source, meta tags, and mailto links across multiple pages.

### 🚪 Port Scanning
Scans 18 ports including dangerous services. Automatically flags exposed database/cache ports:

| Port | Service | Severity |
|---|---|---|
| 6379 | Redis (unauthenticated) | CRITICAL |
| 27017 | MongoDB (unauthenticated) | CRITICAL |
| 9200 | Elasticsearch | CRITICAL |
| 8888 | Jupyter Notebook | CRITICAL |
| 3306 | MySQL | HIGH |
| 5432 | PostgreSQL | HIGH |
| 445 | SMB (ransomware risk) | HIGH |

### 🤖 AI Analysis (Optional)
Integrates with Claude AI to generate executive summaries, attack narratives, and remediation recommendations. Requires Anthropic API key.

### 📊 Professional Reports
Dark-mode HTML report with severity breakdown, CVE table, MITRE ATT&CK mapping, technology stack, and email findings. JSON export included.

## Usage

```bash
ghostrecon <target> [OPTIONS]
```

The target can be passed directly without `--target`:

```bash
ghostrecon example.com
ghostrecon 192.168.1.1
ghostrecon example.com --mode redteam --ai --api-key sk-ant-...
```

### All Flags

| Flag | Description |
|---|---|
| `target` | Target hostname or IP (positional) |
| `--target`, `-t` | Alternative target flag |
| `--mode`, `-m` | `pentest` (default) or `redteam` |
| `--ai` | Enable Claude AI analysis |
| `--api-key`, `-k` | Anthropic API key |
| `--output`, `-o` | Output directory (default: `./reports`) |
| `--stealth` | Enable stealth mode (delays + UA rotation) |
| `--interactive` | Pause between phases |
| `--subdomains` | Enable subdomain enumeration |
| `--screenshot` | Enable Playwright screenshots |
| `--dirbrute` | Enable directory brute-force |
| `--pdf` | Export report as PDF |
| `--deep` | Use the 250k+ endpoint / 150k+ subdomain permutation wordlists (with `--dirbrute`/`--subdomains`) |
| `--shodan-key` | Shodan API key to enrich recon with host data (or `SHODAN_API_KEY` env var) |
| `--list-plugins` | Print registered plugins, phases and dependency graph, then exit |
| `--config` | Path to custom YAML config |
| `--no-report` | Skip report generation |

### Examples

```bash
# Quick scan
ghostrecon example.com

# Full pentest with AI
ghostrecon example.com --mode pentest --ai --api-key sk-ant-...

# Red team engagement
ghostrecon example.com --mode redteam --stealth --subdomains --screenshot --dirbrute

# With PDF export
ghostrecon example.com --pdf

# Deep discovery — 250k+ paths / 150k+ subdomains instead of the curated defaults
ghostrecon example.com --dirbrute --subdomains --deep

# Using environment variable for API key
export ANTHROPIC_API_KEY=sk-ant-...
ghostrecon example.com --ai
```

## Architecture

GhostRecon is built as a **plugin pipeline**, not a hard-coded script. Every capability
(recon, web analysis, dirbrute, CVE correlation, AI analysis, report generation, ...) is a
`Plugin` subclass that self-registers into `core/registry.py` and declares:

- `depends_on` — which other plugins must finish first (e.g. web analysis needs recon's
  open-port data)
- `enabled(ctx)` — whether it should run at all for this engagement (driven by CLI flags)

At run time, `core/pipeline.py` topologically sorts the enabled plugins into **waves**:
every plugin in a wave has all its dependencies already satisfied, so the whole wave runs
concurrently with `asyncio.gather` instead of one phase waiting on the next for no reason.
A typical `--subdomains --ai` run looks like this:

```
Wave 1: recon, subdomain                                    (no shared dependencies)
Wave 2: web, fingerprint, default_creds, dirbrute*, shodan*  (all only need recon)
Wave 3: jwt_analyzer, waf_bypass, cve, screenshot*           (need web / fingerprint)
Wave 4: msf_bridge                                           (needs cve)
Wave 5: opsec                                                (needs everything above)
Wave 6: ai_engine*                                           (needs opsec)
Wave 7: report                                               (needs everything)
```
`*` = only included when its flag/API key is set.

Adding a new scan capability means writing one plugin file and registering it in
`core/bootstrap.py` — `main.py` never needs to change. Two previously-implemented but
unwired modules, `waf_bypass` and `shodan_recon`, are now live plugins in the default
pipeline (Shodan enrichment activates automatically when `--shodan-key` is passed).

Supporting pieces:
- `core/config.py` — typed, layered settings (`pydantic` models): built-in defaults →
  `config.yaml` → environment variables (`GHOSTRECON_*`) → CLI flags. A malformed
  `config.yaml` value now raises a clear validation error instead of failing silently
  deep inside some module.
- `core/context.py` — a single `ScanContext` object (target state + settings + console +
  structured logger + CLI flags) passed to every plugin, replacing the old pattern of
  each module function taking its own bespoke argument list.
- `utils/logger.py` — structured, credential-masking file logging (`logs/engagement_*.log`)
  of every plugin's start/duration/errors — previously written but never actually wired
  into the CLI.

Run `ghostrecon --list-plugins` to print the registered plugins, their phase, and their
dependency list without starting a scan.

## Configuration

Edit `config/config.yaml` to customize scan behavior:

```yaml
scan:
  timeout: 2.0
  max_parallel_ports: 50

ai:
  model: "claude-sonnet-4-6"
  max_tokens: 2000

stealth:
  min_delay: 1.0
  max_delay: 3.0
  rotate_ua: true

paths:
  wordlists: "./config/wordlists"
  reports: "./reports"
```
